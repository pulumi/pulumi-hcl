# Contributing

## Release process

Releasing requires an unreleased fragment. When a release is available, a weekly job opens a
release PR every Monday at 09:00 UTC, then approves it and queues it to merge. Renovate should
open a PR to bump the version of HCL bundled with [pulumi/pulumi](https://github.com/pulumi/pulumi)
in the next day or so.

### Release Mechanics

Releases are driven by [changie](https://changie.dev) and [GoReleaser](https://goreleaser.com). The flow is:

1. **Add a changelog fragment with every user-visible PR.** 

Run `changie new` from the repo root and answer the prompts:
- **Component**: one of `language-host`, `converter`, `codegen`, `runtime`.
- **Kind**: `Improvements` (auto-bumps minor) or `Bug Fixes` (auto-bumps patch).
- **Body**: a short description written from the user's perspective.
- **PR**: the GitHub PR number this change ships in.

This writes a file under `.changes/unreleased/`. Commit it with your PR.

The `Dependencies` kind is reserved for automated Renovate updates: a `postUpgradeTasks`
hook runs `make renovate` (see `.github/scripts/renovate-changelog.sh`), so those
fragments carry no component or PR number.

2. **Cut a release PR.** 

When you're ready to ship, run:

```sh
changie batch auto      # or an explicit version, e.g. `changie batch v0.2.0`
changie merge
```

`changie batch` consumes everything in `.changes/unreleased/` and writes
`.changes/<version>.md`. `changie merge` rewrites the top-level `CHANGELOG.md` from the
header template plus all batched versions. Open a PR titled "Release `<version>`" with
just those two changes.

3. **Merge the release PR to `master`.** 

The `Release` workflow fires on any push to `master` that touches `CHANGELOG.md`. It:
- reads the latest version with `changie latest`,
- creates and pushes a `v<version>` git tag,
- runs GoReleaser, which builds `pulumi-language-hcl` and `pulumi-converter-hcl` for
  linux/darwin/windows × amd64/arm64 and publishes them to a GitHub release whose body is
  `.changes/<version>.md`.
- pushes the binaries to `get.pulumi.com`
- pushes to the registry
- publishes all SDKs

The workflow no-ops if the tag already exists, so re-running it is safe.

Steps (2) and (3) are fully automated by a weekly job, which every Monday at 09:00 UTC
batches any unreleased changes into a release PR, approves it and queues it to merge, and
pings Slack (or pings that no release is needed). To release sooner, follow step (2) by
hand and merge the result.

### Versioning

The `auto` argument to `changie batch` picks the next version from the fragments: any
`Improvements` entry bumps minor, otherwise `Bug Fixes` bumps patch. Override by passing
an explicit `vX.Y.Z` when a release needs a major bump or a different version than `auto`
would compute.

## SDK Publishing

In addition to being a converter & language, HCL is a provider:
[`pulumi-resource-hcl`](cmd/pulumi-resource-hcl/main.go). The provider has SDKs which need to be published in every
language that Pulumi supports:

- [TypeScript](https://www.npmjs.com/package/@pulumi/hcl)
- [Python](https://pypi.org/project/pulumi-hcl/)
- [C#](https://www.nuget.org/packages/Pulumi.Hcl)
- [Java](https://central.sonatype.com/artifact/com.pulumi/hcl)
- [Go](https://pkg.go.dev/github.com/pulumi/pulumi-hcl/sdk/go/hcl)

Each SDK is generated by running `pulumi package gen-sdk
"${RUNNER_TEMP}/pulumi-resource-hcl"` with latest `pulumi`. `pulumi-resource-hcl` is tested
before publishing, but the SDKs generated from it are not. We add [minimal per-language
customization](https://github.com/pulumi/pulumi-hcl/blob/734fe1a462facbfd33c58d50a3e1a4e35b91b36f/pkg/server/module_resource_schema.go#L76-L82), and so assume that a valid provider will produce valid schemas. If that
fails, the fault is upstream in [`pulumi/pulumi`](https://github.com/pulumi/pulumi).

Each publish regenerates SDKs into the [`sdk-releases`](https://github.com/pulumi/pulumi-hcl/tree/sdk-releases) branch, and from there pushes
to the relevant package registry. SDKs are never checked into `master`. `sdk-releases`
shares no history with `master`.

TypeScript, Python & C# all use trusted publishing to publish their SDKs. Go directly tags
the `sdk-releases` branch (tags look like `sdk/go/v${VERSION}`). Java uses keys from the
[imports/github-secrets](https://app.pulumi.com/pulumi/esc/imports/github-secrets) ESC environment to publish to maven central.
